# პროტოკოლი, ვერსია 1

**სტატუსი.** დოკუმენტის ფორმა (`world`) და ოპერაციები (`ops`) ეტაპი 0-ში დამტკიცებისთვისაა გამზადებული. მოვლენების ცხრილი სამუშაო ვარიანტია და საბოლოოდ ეტაპ 3-ში დაზუსტდება.

## 1. მოდელი

- **სიმართლის წყარო.** სერვერი (Node + Socket.IO) ინახავს თითოეული ოთახის სამყაროს და ცვლილებების თანმიმდევრობას განსაზღვრავს. ყოველი მიღებული ცვლილება სამყაროს ვერსიას (`rev`) ერთით ზრდის.
- **ცვლილების ერთეული.** ცვლილება ობიექტის ზედა დონის თვისებას ეხება. ორი სხვადასხვა თვისების ცვლილება ერთმანეთს არ ეჯახება. ერთსა და იმავე თვისებაზე იმარჯვებს ის, რაც სერვერამდე ბოლოს მივიდა. ეს Figma-ს მოდელია.
- **ოპტიმისტური ჩვენება.** კლიენტი საკუთარ ცვლილებას მაშინვე აჩვენებს. სანამ სერვერი მას დაადასტურებს, იმავე თვისებაზე სხვისგან მოსულ ცვლილებას უგულებელყოფს. თუ სერვერმა უარყო, ცვლილებას უკან აბრუნებს.
- **ID-ები.** კლიენტი ობიექტის ID-ს თავად ქმნის ფორმით `<playerId>:<counter>`. სერვერისა და AI-ის ობიექტებს აქვთ `srv:<counter>`.
- **Play რეჟიმი ლოკალურია.** თითოეული მოთამაშე საერთო დონეს თავის Mac-ზე თამაშობს. თამაშის მდგომარეობა სერვერზე არ იგზავნება.

## 2. სამყარო და ოპერაციები

- სამყაროს ფორმა: [`schema/world.schema.json`](schema/world.schema.json)
- ოპერაციების პაკეტი: [`schema/ops.schema.json`](schema/ops.schema.json)
- შინაარსის წესები და ვალიდაცია: [`rules.md`](rules.md)

| op | რას აკეთებს |
| --- | --- |
| `create` | ქმნის ობიექტს სრული მონაცემით |
| `update` | ცვლის ზედა დონის თვისებებს (`x`, `y`, `w`, `h`, `color`, `door`, `label`, `icon`) |
| `delete` | შლის ობიექტს. წაშლილი მონაცემი მხოლოდ წამშლელის Undo ისტორიაში რჩება |
| `set_world` | ცვლის `start`-ს ან `flag`-ს |
| `set_objectives` | ანაცვლებს დავალებების მთელ სიას |

ბადის ზომა ოთახის შექმნისას ფიქსირდება და მერე აღარ იცვლება.

სერვერი პაკეტს ან მთლიანად იღებს, ან მთლიანად უარყოფს. პაკეტის გამოყენების შემდეგ სამყარო [`rules.md`](rules.md)-ის მე-7 პუნქტის ვალიდაციას უნდა გადიოდეს.

## 3. Socket.IO მოვლენები (სამუშაო ვარიანტი)

პასუხის მომლოდინე მოვლენები Socket.IO-ს acknowledgement-ს (`emitWithAck`) იყენებენ.

| მოვლენა | მიმართულება | payload | პასუხი |
| --- | --- | --- | --- |
| `room:create` | კლიენტი → სერვერი | `{ name, grid }` | `{ roomCode }` |
| `room:join` | კლიენტი → სერვერი | `{ roomCode, name, token? }` | `{ playerId, token, color, world, rev, players }` |
| `doc:submit` | კლიენტი → სერვერი | `OpBatch` | `{ ok: true, rev }` ან `{ ok: false, code, message }` |
| `doc:ops` | სერვერი → ყველა | `{ rev, author, ops }` | — |
| `doc:snapshot` | სერვერი → კლიენტი | `{ world, rev }` | — |
| `presence:update` | კლიენტი → სერვერი | `{ cursor: {x, y} \| null, selection: [id] }` | — |
| `presence` | სერვერი → სხვები | `{ playerId, cursor, selection }` | — |
| `players` | სერვერი → ყველა | `{ players: [{ playerId, name, color, online }] }` | — |
| `solve:result` | სერვერი → ყველა | `{ rev, solvable, steps?, unreachable }` | — |
| `history:undo` | კლიენტი → სერვერი | `{}` | `{ ok, rev? }` |
| `cmd:send` | კლიენტი → სერვერი | `{ text, source: "voice" \| "text" }` | `{ cmdId }` (ეტაპი 4) |
| `cmd:status` | სერვერი → ყველა | `{ cmdId, by, text, status, say? }` (ეტაპი 4) | — |
| `mediator:proposal` | სერვერი → ყველა | `{ proposalId, text, ops }` (ეტაპი 4) | — |
| `mediator:vote` | კლიენტი → სერვერი | `{ proposalId, accept }` (ეტაპი 4) | — |

## 4. კავშირის აღდგენა

1. სერვერზე ჩართულია Socket.IO-ს connection state recovery. მოკლე გათიშვის შემდეგ ის აღადგენს socket-ის id-ს, ოთახს და გამოტოვებულ მოვლენებს.
2. თუ აღდგენა ვერ მოხერხდა (`socket.recovered === false`), კლიენტი თავიდან აგზავნის `room:join`-ს თავისი `token`-ით და იღებს `doc:snapshot`-ს.
3. დაუდასტურებელ ცვლილებებს კლიენტი ახალ ასლზე ხელახლა აგზავნის. სერვერი მათ ჩვეულებრივად ამოწმებს.

## 5. ვერსიები

ყველა JSON-ს აქვს `schemaVersion`. სქემის შეუთავსებელი ცვლილება ვერსიას ზრდის, სერვერი კი ძველ ვერსიას `room:join`-ზე შეცდომით `unsupported_version` პასუხობს.
