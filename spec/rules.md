# თამაშის წესები, ვერსია 1

ეს დოკუმენტი ნორმატიულია: სერვერი (TypeScript) და აპი (Dart) ორივე ზუსტად ამ წესებით უნდა მუშაობდეს. ორივე იმპლემენტაცია `fixtures/` საქაღალდის ერთსა და იმავე ტესტებს გადის. თუ კოდი და ეს დოკუმენტი ერთმანეთს ეწინააღმდეგება, მცდარია კოდი.

## 1. ბადე

- სამყარო არის `w × h` ზომის ბადე. ნაგულისხმევი ზომაა 24 × 14, მაქსიმალური 40 × 24.
- უჯრა არის მთელ რიცხვთა წყვილი `(x, y)`. სათავე ზედა მარცხენა კუთხეშია, `x` იზრდება მარჯვნივ, `y` ქვემოთ.
- `start` და `flag` ორი სხვადასხვა უჯრაა ბადის შიგნით.

## 2. ობიექტები

ყველა ობიექტს აქვს `id`, `type`, `owner` და, სურვილისამებრ, `label` და `icon`. `label` და `icon` მხოლოდ გარეგნობაა და წესებზე გავლენა არ აქვს.

| type | გეომეტრია | დამატებითი ველები |
| --- | --- | --- |
| `wall` | მართკუთხედი `x, y, w, h` | — |
| `lava` | მართკუთხედი | — |
| `bridge` | მართკუთხედი | — |
| `castle` | მართკუთხედი, `w ≥ 3`, `h ≥ 3` | `door: { side, offset, color }` |
| `door` | უჯრა `x, y` | `color` |
| `key` | უჯრა | `color` |
| `treasure` | უჯრა | — |
| `coin` | უჯრა | — |

ფერებია `red`, `blue` და `gold`.

### 2.1 ციხე

ციხე ავტომატურად იშლება:

- **კედლები**: მართკუთხედის კონტურის ყველა უჯრა.
- **კარი**: კონტურის ერთი უჯრა, რომელსაც კედლის ნაცვლად კარი უჭირავს.
- **შიგნით**: შიდა უჯრები ჩვეულებრივი მიწაა.

კარის უჯრის მდებარეობა:

| side | უჯრა | offset-ის დასაშვები მნიშვნელობები |
| --- | --- | --- |
| `left` | `(x, y + 1 + offset)` | `0 … h − 3` |
| `right` | `(x + w − 1, y + 1 + offset)` | `0 … h − 3` |
| `top` | `(x + 1 + offset, y)` | `0 … w − 3` |
| `bottom` | `(x + 1 + offset, y + h − 1)` | `0 … w − 3` |

თუ `door.color` არის `null`, კარის ადგილას ღია გასასვლელია (მიწა). თუ ფერი მითითებულია, იქ იმ ფერის კარია.

## 3. რელიეფის გამოთვლა (რასტერიზაცია)

თითოეულ უჯრას აქვს ზუსტად ერთი რელიეფი. თუ უჯრას რამდენიმე ობიექტი ფარავს, იმარჯვებს უფრო მაღალი პრიორიტეტი:

1. კარი (`door` ობიექტი ან ციხის ფერადი კარი)
2. კედელი (`wall` ან ციხის კონტური)
3. ხიდი
4. ლავა
5. მიწა (ნაგულისხმევი)

ერთი და იმავე პრიორიტეტის ორი კარის შემთხვევაში იმარჯვებს ის, რომელიც `entities` მასივში უფრო გვიან დგას. ციხის ღია გასასვლელი (`color: null`) კონტურის ამ უჯრიდან კედელს აშორებს. სხვა ობიექტი თუ იმავე უჯრას ფარავს, მაინც თავისი პრიორიტეტით მოქმედებს.

ნივთები (`key`, `treasure`, `coin`) რელიეფი არ არის, ისინი ცალკე ფენაზე დევს. ერთ უჯრაზე რამდენიმე ნივთი შეიძლება იყოს.

| რელიეფი | შესვლა |
| --- | --- |
| მიწა, ხიდი | შეიძლება |
| კედელი | არ შეიძლება |
| კარი (ფერი C) | შეიძლება მხოლოდ მაშინ, თუ მოთამაშეს C ფერის გასაღები აქვს |
| ლავა | Play რეჟიმში სიკვდილია, solver-ისთვის შეუღწევადია |

## 4. თამაშის რეჟიმი (Play)

მდგომარეობა: პოზიცია, აღებული გასაღების ფერები, აღებული ნივთების `id`-ები, სიკვდილების რაოდენობა და `won`.

1. **დაწყება.** პოზიცია `start`-ია, ინვენტარი ცარიელია. თუ `start`-ზე ნივთები დევს, ისინი მაშინვე აიღება.
2. **ნაბიჯი.** შეყვანაა `up`, `down`, `left` ან `right`. თითოეული შეყვანა ერთ უჯრაზე გადაადგილების მცდელობაა.
3. **ბადის გარეთ, კედელი, ჩაკეტილი კარი.** მოთამაშე ადგილზე რჩება.
4. **ლავა.** `deaths` ერთით იზრდება და ყველაფერი საწყის მდგომარეობას უბრუნდება: პოზიცია `start`-ია, ინვენტარი ცარიელია, ყველა ნივთი თავის ადგილზე ბრუნდება (პუნქტი 1).
5. **სხვა შემთხვევაში** მოთამაშე გადადის და ამ უჯრის ყველა ნივთს იღებს: გასაღები ფერს ამატებს, განძი და მონეტა `id`-ს.
6. **მოგება.** თუ ნაბიჯის შემდეგ პოზიცია `flag`-ია და ყველა დავალება შესრულებულია, `won = true`. ამის შემდეგ შეყვანა აღარ მოქმედებს.

გასაღები არ იხარჯება და კარი თავისით არ იკეტება.

## 5. დავალებები

| type | შესრულებულია, როცა |
| --- | --- |
| `collect` (`target`) | `target` ნივთი (განძი ან მონეტა) აღებულია |
| `collect_count` (`item: "coin"`, `count`) | აღებული მონეტების რაოდენობა `≥ count` |

ბოლო დავალება ყოველთვის იგულისხმება: დროშასთან მისვლა. თუ დავალებების სია ცარიელია, საკმარისია დროშასთან მისვლა. დავალებების შესრულების თანმიმდევრობა არ არის დადგენილი.

## 6. Solver

Solver პასუხობს, შეიძლება თუ არა მოგება, და რამდენი ნაბიჯი სჭირდება უმოკლეს გზას.

- **ძებნა.** BFS მდგომარეობებზე `(x, y, გასაღებები, აღებული მნიშვნელოვანი ნივთები)`. მნიშვნელოვანია ნივთი, რომელსაც დავალება ეხება: `collect`-ის `target` ან ნებისმიერი მონეტა, თუ `collect_count` არსებობს. ლავაზე გადასვლა არ განიხილება.
- **`steps`.** ნაბიჯების მინიმალური რაოდენობა საწყისი მდგომარეობიდან მოგებამდე.
- **`unreachable`.** სია იმისა, რისი მიღწევაც საერთოდ შეუძლებელია, სტაბილური თანმიმდევრობით:
  1. ყველა `collect:<target>`, თუ `target`-ის უჯრა მიუწვდომელია, `objectives` მასივის თანმიმდევრობით;
  2. `collect_count:coin`, თუ მისაწვდომი მონეტები ყველაზე დიდ `count`-ზე ნაკლებია;
  3. `flag`, თუ დროშის უჯრა მიუწვდომელია.

**მისაწვდომი უჯრები (R)** არის ყველა უჯრა, რომელიც რომელიმე მისაწვდომ მდგომარეობაში გვხვდება.

**თვისება.** გასაღები და ნივთი არასდროს იკარგება, მოძრაობა კი შექცევადია. ამიტომ R-ის ყველა უჯრა ერთ თამაშშიც მიიღწევა. მოგება შესაძლებელია მაშინ და მხოლოდ მაშინ, როცა `unreachable` ცარიელია.

## 7. სემანტიკური ვალიდაცია

JSON სქემა ფორმას ამოწმებს, ეს წესები კი შინაარსს. **შეცდომის** შემთხვევაში სერვერი ცვლილებას უარყოფს.

| კოდი | შეცდომა |
| --- | --- |
| `out_of_bounds` | ობიექტი, `start` ან `flag` ბადის გარეთაა |
| `duplicate_id` | ორ ობიექტს ერთი `id` აქვს |
| `start_equals_flag` | `start` და `flag` ერთი უჯრაა |
| `invalid_castle_door` | `offset` დასაშვებ დიაპაზონს სცდება |
| `objective_target` | `collect`-ის `target` არ არის არსებული განძი ან მონეტა |
| `collectible_limit` | განძი და მონეტა ერთად 8-ზე მეტია |

**გაფრთხილება** ცვლილებას არ აჩერებს, მაგრამ ედიტორი მას აჩვენებს:

| კოდი | გაფრთხილება |
| --- | --- |
| `protected_cell` | `start` ან `flag` შეუღწევად რელიეფზეა |
| `item_on_blocked` | ნივთი კედელზე ან ლავაზე დევს |
| `item_on_start` | ნივთი `start`-ზე დევს |
