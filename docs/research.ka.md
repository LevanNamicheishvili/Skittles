# Hacktoberfest Multiplayer: კვლევა და პროდუქტის დასაბუთება

Oct 17, 2026 · @levan namicheishvili

## მთავარი დასკვნა

ტრეკ 02-ზე ვაკეთებთ Skittles-ს. ორი ადამიანი, თითო თავისი აგენტით, ერთ ცოცხალ თამაშს ცვლის, სანამ მესამე თამაშობს. სისტემა ამოწმებს, რომ მათი ცვლილებები ერთად თამაშს არ ტეხს.

ფრაზა სცენისთვის: Figma-მ ასწავლა ადამიანებს ერთად ხატვა. ჩვენ ვასწავლით მათ აგენტებს ერთად ქმნას ისე, რომ ერთმანეთის ნამუშევარი არ გატეხონ.

რატომ არის ეს სწორი არჩევანი:

1. **ტრეკი ზუსტად ამას ითხოვს.** ოთხივე პირობას სცენაზე პირდაპირ ვაჩვენებთ. დეკის მაგალითებშიც თამაშის რედაქტირებაა.
2. **რთულ ნაწილს ვწყვეტთ.** ბაიტების სინქრონიზაცია უკვე გადაწყვეტილია. ღიაა განზრახვის კონფლიქტი: ორი სწორი ცვლილება, რომელიც ერთად მიზანს ტეხს. Roblox გვირჩევს ერთ ჩატში ვიმუშაოთ. Lovable კონფლიქტს ერთი ჩამწერით გამორიცხავს. Nilo თვითონ წერს გატეხილ ცვლილებებზე.
3. **თამაშში ამას მანქანა ამოწმებს.** სოლვერი გეუბნება, მიიღწევა თუ არა ფინიში. დოკუმენტში ასეთი შემოწმება არ არსებობს. ამიტომ აქ სისტემა დამტკიცებადად მუშაობს და არა რწმენით.
4. **ჟიურის ენაზე ვლაპარაკობთ.** აქტორი და ერთი ჩამწერი, ლოგი, ოპერაციების ინტერპრეტატორი, ვიზუალური diff, აგენტის ჩატი, ადამიანის დამტკიცება. შვიდივე წევრს თავისი ნაწილი აქვს დემოში.
5. **დროში ეტევა.** წესები, სოლვერი და 66 ტესტი უკვე დაწერილია და მათი გამოყენება დაშვებულია. დარჩენილი დრო ოთახს, აგენტებს და დემოს ხმარდება.

რას ვერ გიპირდები: გამარჯვების შანსს ვერ შევაფასებ. მომხმარებლებთან ინტერვიუ არ გვქონია.

ახლავე: სამ მონაწილესთან ხუთწუთიანი საუბარი და ოთახის აწყობა. Discord-ში მხოლოდ ჩაბარების ფორმატს და დემოს ხანგრძლივობას ვკითხულობთ.

## რას ითხოვს Hacktoberfest

ფაქტები ოფიციალური დეკიდან, საიტიდან და Terms გვერდიდან.

- Hacktoberfest Georgia 2026 იმართება 17–18 ოქტომბერს, თავისუფალ უნივერსიტეტში. ორგანიზატორები არიან DevTherapy, Lovable და FLP.

- ტრეკს ოთხი პირობა აქვს. აგენტმა იცის, რა შეცვალა მეორე აგენტმა. კონფლიქტი არ ხდება. ყველაფერი ცოცხლად ახლდება, როგორც Figma-ში. სცენაზე ორი ადამიანი ცოცხლად აჩვენებს.
- დეკის მაგალითებშია საერთო ვიდეოს ან თამაშის რედაქტირება.
- შეფასების სამი კითხვაა: პრობლემა ნათელია? გადაწყვეტა კრეატიულია? პრობლემას მართლა წყვეტს? ბიზნეს მოდელი, ფასი და გლობალური გაფართოება არ ფასდება.

- საიტის მიხედვით, სტეკი თავისუფალია, გუნდში 5 კაცამდეა. Lovable-ის პრიზისთვის Lovable-ის ანგარიშია საჭირო.

## პრობლემა და მტკიცებულება

პრობლემა ერთი წინადადებით: როცა ორი ადამიანი ერთ ნამუშევარს თავისი აგენტით ცვლის, ყველაზე საშიში კონფლიქტი ტექსტში არ ჩანს. ეს განზრახვის კონფლიქტია. ორი ცვლილება ცალ-ცალკე სწორია, ერთად კი მიზანს არღვევს.

მაგალითი. ნინო ლავის მდინარეს ამატებს. გიორგი ფინიშს კარით და გასაღებით კეტავს. ორივე ცვლილება სწორია. ერთად კი მოთამაშე ფინიშამდე ვეღარ აღწევს. ამას ვერც Git დაინახავს და ვერც CRDT, რადგან ბაიტებში კონფლიქტი არ არის.

ბაიტების სინქრონიზაცია ცნობილი ამოცანაა. Figma-მ და CRDT ბიბლიოთეკებმა ის კარგად გადაწყვიტეს. ღია ამოცანა სხვაა: როგორ გაიგონ ორმა აგენტმა, რომ მათი ცვლილებები ერთად მიზანს არღვევს, და როგორ შესთავაზონ ადამიანებს გამოსავალი.

## პროდუქტი: Skittles

Skittles სამუშაო სახელია. ასე ჰქვია Mars-ის კანფეტსაც, რომელიც რეგისტრირებული სავაჭრო ნიშანია, ამიტომ ჰაკათონის მიღმა გამოყენებამდე სახელი უნდა შემოწმდეს.

ერთი წინადადებით: ორი ადამიანი, თითო თავისი აგენტით, ერთ ცოცხალ თამაშს ცვლის, სანამ მესამე მას თამაშობს. სისტემა ყოველ ცვლილებას ავტორით წერს და ამოწმებს, რომ თამაში ისევ გავლადია. თუ ორი ცვლილება ერთად თამაშს ტეხს, მედიატორი გვთავაზობს გამოსავალს, რომელიც ორივეს იდეას ინარჩუნებს. საბოლოოდ ირჩევს ადამიანი.

რატომ თამაში? თამაში ყველაზე პატარა სამყაროა, სადაც მიზნის შემოწმება მანქანას შეუძლია. დოკუმენტში ვერ შეამოწმებ, ორი რედაქტირების შემდეგ ტექსტი ისევ კარგია თუ არა. დონეში შეგიძლია: სოლვერი გეუბნება, მიიღწევა თუ არა ფინიში. ამიტომ აქ განზრახვის კონფლიქტი გაზომვადი ხდება.

- ობიექტები: კედელი, გზა, ლავა, ხიდი, გასაღები, დაკეტილი კარი, ფინიში.

ტექნიკური არჩევანი:

- სერვერი: Node და WebSocket. ერთი პროცესი ერთი ოთახის აქტორია.
- კლიენტი: ბრაუზერი, Canvas. დასაყენებელი არაფერია, სცენაზე ორი ლეპტოპი და პროექტორი საკმარისია.
- წესები და სოლვერი: დღეს დაწერილი TypeScript კოდი, 66 ტესტით. წინასწარ დაწერილი კოდი დაშვებულია, ამიტომ პირდაპირ ვიყენებთ.
- აგენტი: LLM tool use, JSON სქემით შეზღუდული. მოდელი ავირჩიოთ სიჩქარით, ერთი ცვლილება 5 წამამდე უნდა ჯდებოდეს.

იგივე მექანიზმი მუშაობს ყველგან, სადაც მიზნის შემოწმება შეიძლება: განრიგი, ბიუჯეტი, კონფიგურაცია. ჰაკათონზე ამას არ ვყიდით, მხოლოდ ერთი წინადადებით ვახსენებთ.

## დამატება: Playtest Dev Mode

მოთამაშეს შეუძლია თამაშის შიგნიდან გაგზავნოს რეპორტი (ღილაკით ან F-ით). Dev mode პრობლემას თვითონაც ამჩნევს: მაგალითად, როცა მოთამაშე ერთსა და იმავე უჯრაზე ლავაში ორჯერ ვარდება. მოთამაშეს არაფრის ახსნა არ სჭირდება. რეპორტს თამაში თვითონ ურთავს:

- პოზიციას და ვერსიას;
- გავლილ გზას;
- ჩავარდნებს და აღებულ გასაღებებს;
- იმ ობიექტებს, რომლებიც პრობლემის ადგილას დგას.

რეპორტი იმ ავტორთან მიდის, ვისაც ეს ობიექტები ეკუთვნის. მისი აგენტი შესწორებას ამზადებს და ოთახი მას წინასწარ ამოწმებს. ავტორი ერთი დაჭერით ამტკიცებს, ცვლილება კი ცოცხალ თამაშში უსაფრთხო მომენტში ჯდება.

რეალურ აგენტზე ასე შემოწმდა:

1. ლუკა ორჯერ ჩავარდა ნინოს ლავაში (11, 8) უჯრაზე.
2. Dev mode-მა ნინოს თვითონ გაუგზავნა სიგნალი.
3. ნინოს აგენტმა შესთავაზა, ლავა ერთი რიგით შეემოკლებინა: მდინარე რჩება, გადასასვლელი კი სამართლიანი ხდება.
4. ნინომ დაამტკიცა და დონე v2 გახდა.

ბაზარზე „AI თამაშობს და ასწორებს“ ტიპის ხელსაწყოები უკვე არის. ქვემოთ ძიების შედეგებია და მწარმოებლების განცხადებებს ეყრდნობა, შემოწმებული არ არის.
